# API Reference

<Divider />

## Ballot by Address

Resolve Populist's races and ballot measures for a US voting address in a
specific election.

This endpoint returns informational election data. It is not an official sample
ballot, voter-registration check, polling-place lookup, or statement of voter
eligibility. Direct users to the relevant election authority for official
information.

### Endpoint

<CodeBlock
  code={`POST https://api.populist.us/api/v1/elections/{electionId}/ballot`}
  language="http"
/>

You need an election UUID before making this request. The endpoint does not
discover elections. Obtain the configured election ID, environment base URL,
and bearer API key during onboarding.

### Filter candidates by endorsement

Add `endorserId` as an optional organization UUID:

<CodeBlock
  code={`POST /api/v1/elections/{electionId}/ballot?endorserId={organizationId}`}
  language="http"
/>

This filters each race's `candidates` array to candidates endorsed by the
organization. It does not remove races, ballot measures, result totals, or
winner references. A race can therefore remain present with an empty
`candidates` array.

[OpenAPI contract](/openapi/rest-v1.yaml).

#### Election

`election` contains the stable ID, slug, title, optional description, optional
state, and `YYYY-MM-DD` election date.

#### Races

Each race contains identity and election fields, the office, running
candidates, reported results, and public related embeds.

- `raceType` is `primary` or `general`.
- `voteType` is `plurality` or `rankedchoice`.
- `office.electionScope` is `national`, `state`, `county`, `city`, or
  `district`.
- `office.politicalScope` is `local`, `state`, or `federal`.
- Candidate and incumbent party, contact, image, and asset fields can be
  `null`.
- Result counts and percentages can be `null` until results are available.
  Percentages are percentage points rounded to one decimal place.
- `winners` can be empty before a race is called.
- Administrative embed-origin restrictions are never exposed.

#### Ballot measures

Each measure contains its ID, title, optional description, state, measure code,
nullable vote and precinct counts, and nullable election scope.

### Geographic coverage

Always inspect `data.coverage` before presenting the response as an
address-specific ballot.

<DocsTable
  headers={["Address state", "Race coverage", "Ballot-measure coverage"]}
  rows={[
    ["Minnesota", <code>address_specific</code>, <code>address_specific</code>],
    ["Texas", <code>address_specific</code>, <code>statewide_only</code>],

      "Other supported state or territory",
      <code>statewide_only</code>,
      <code>statewide_only</code>,
    ],

`statewide_only` means district and local matching is unavailable. It does not
guarantee that every statewide record is present. Display or otherwise handle
`coverage.warnings`; branch on the stable coverage values rather than warning
text.

### Ordering

Arrays have deterministic ordering:

- Races use office priority, district, seat, title, and ID.
- Candidates and incumbents use last name, first name, and ID.
- Candidate vote rows and related embeds use ID.
- Ballot measures use title and ID.

Do not use this ordering as a synchronization cursor.

### Address privacy

Use HTTPS and prevent application and proxy logs from recording request bodies.
The address is never returned. `line2` is discarded during validation.

An exact cached address can be reused without geocoding. On a cache miss,
street, city, state, and ZIP are sent to the configured geocoding service to
derive coordinates and districts. A temporary address record is used during
selection and Populist attempts to remove newly created records after
processing when they are not connected to a user profile.

Abnormal termination or cleanup failure can interrupt that best-effort
removal. Confirm contractual retention, subprocessors, and deletion
requirements during onboarding before sending production personal data.

### Client checklist

- Keep the API key in a trusted backend.
- Test a known Minnesota address and verify both coverage fields.
- Test invalid JSON, invalid ZIP, unknown election, and unresolvable address.
- Ensure request and response logs do not contain the address.
- Propagate `X-Request-Id` without personal data.
- Implement bounded 429, 503, and 504 retries with jitter.
- Decide how empty candidate, race, and ballot-measure arrays display.
- Describe the result as informational rather than an official ballot.
